# 검증 보고서 양식 설계안 — `!검증` PDF

> **상태**: 설계안 (구현 전 — 양식 확정 후 코딩)  
> **작성일**: 2026-08-14  
> **목표**: `!검증`이 **비전공자도 읽는 성적 보고서(PDF)** 를 만들고,  
> analyze와 같이 **GitHub Release 다운로드 링크**를 돌려준다.  
> **근거 데이터**: 기존 D29 A–D 패널 (`reports/perf/`) — 숫자는 그대로, **말과 구성만 보고서화**.

---

## 1. 한 줄 콘셉트

지금 `!검증` = 표·차트 덤프.  
바꿀 것 = **“우리 SEPA 스크리너, 요즘 성적 어때요?”** 에 답하는 **짧은 한글 보고서 PDF**.

배달 방식은 `!sepa.anal` / `!sepa.go` 와 동일:

```text
!검증
  → reports/perf/검증보고서_YYYYMMDD.pdf
  → GitHub Release 업로드 (예: sepa-검증-YYYYMMDD)
  → 콘솔에 PDF 직접 다운로드 URL + 릴리즈 페이지 URL 출력
  → (선택) ZIP / board PNG — 안드로이드에서 PDF가 안 받을 때
```

## 2. 독자 · 톤

| 항목 | 결정(안) |
|---|---|
| 독자 | 비전공 · 개인 투자 참고 (당신) |
| 톤 | 학교 성적표 + 코치 코멘트. 전문용어는 **쉬운 말 → (괄호 원어)** |
| 길이 | **6~8페이지** (길면 안 읽음) |
| 태도 | “지금 결론”이 아니라 **쌓이는 성적표**. 표본 부족 시 빨간 경고 고정 |
| 금지 | 파라미터 자동 변경 권고를 단정적으로 쓰기. “참고 신호”로만 |

---

## 3. 표지·공통 요소

### 표지

- 제목: **SEPA 모델 성적 보고서**
- 부제: 기간(첫 stamp ~ 마지막 stamp) · 생성일 · 표본 일수
- 한 줄 요약(자동 문장):  
  예) *“지금은 관측 7일·5일 수익률만 일부 채워진 단계라, 확정 평가가 아닙니다.”*
- **신뢰 배지** 하나: `자료 부족` / `지켜보는 중` / `해석 가능`  
  (기존 sample_gate를 사람 말로)

### 매 페이지 하단

- “시장 = S&P500(`^GSPC`) 대비 초과수익 · look-ahead 없음”
- “이 보고서는 매매 권유가 아님”

### 용어 미니 사전 (표지 뒷장 또는 부록 반 페이지)

| 쉬운 말 | 뜻 |
|---|---|
| 바구니 | 그날 규칙으로 뽑힌 종목 묶음 |
| 시장보다 잘함 | S&P500보다 수익률이 높음(초과) |
| 중앙값 이상 | Fund 점수가 그날 후보 중위 이상(median+) |
| soft ceiling | RS는 높지만 Fund가 약해서 **일부러 뺀** 종목 |
| 들어옴/나감 | sepaTop 편입(enter) / 편출(exit) |
| 오래 남음 | 리스트에 연속으로 남아 있는 날 수(streak) |

## 4. 본문 목차 (권장 8쪽)

### 1쪽 — 한눈에 보기 (Executive)

- **오늘 질문 4개**에 Yes/No/모름 박스 (게이트에 따라 “모름” 많음 OK)
  1. 우리가 고른 바구니가 시장보다 나았나?
  2. 리스트에 넣고 뺀 타이밍이 괜찮았나?
  3. 오래 남은 종목이 더 나았나?
  4. soft ceiling으로 뺀 종목이 정말 못했나?
- 큰 숫자 3개: 관측 일수 / 5일 성적 준비된 건수 / 신뢰 배지
- **한 문단 코멘트** (템플릿 문장 + 숫자 삽입)

### 2쪽 — 이 보고서가 보는 것 / 안 보는 것

- 본다: 스크리너 규칙의 **사후 성적** (이미 쌓인 go 결과)
- 안 본다: 내일 주가 예측, 자동매매, “이 종목 사라”
- 비유: *매일 시험 본 답안지를 모아 중간 성적표를 만드는 것*

### 3쪽 — A. 바구니 성적 (시장 대비)

- 쉬운 제목: **“우리가 고른 팀이 시장보다 잘했나?”**
- 차트: 5일(우선) 바 차트 + 표(10·21일은 표만 또는 작은 차트)
- 해석 문장 예:  
  *“중앙값 이상 바구니가 5일 평균으로 시장보다 ○○%p 높았습니다.  
  다만 관측 stamp가 N일이라 아직은 ‘참고’ 수준입니다.”*
- soft_drop / fund_q4가 유독 나쁘면 **빨간 한 줄 주의**

### 4쪽 — D. soft ceiling 검사 (정책 핵심)

- 쉬운 제목: **“일부러 뺀 종목, 빼길 잘했나?”**
- 두 막대: 뺀 그룹(soft_drop) vs 남긴 RS≥90(rs90_ok)
- Δ(차이)를 **큰 글씨**로
- 해석 규칙(고정 카피):
  - Δ가 음수(뺀 쪽 더 못함) → *“지금 신호는 규칙이 도움이 되는 쪽”*
  - Δ가 양수 → *“규칙이 좋은 종목을 잘못 잘랐을 수도 — 표본 더 필요”*
  - 게이트 insufficient → *“아직 시험 횟수가 적어 판단 보류”*

### 5쪽 — B. 들어옴 / 나감

- 쉬운 제목: **“넣고 뺀 직후 성적은?”**
- enter / exit 5·10·21일 표 + 5일 차트
- 해석: 편입 직후 초과가 +, 편출 직후가 −면 *타이밍이 대체로 맞다*는 **약한** 신호

### 6쪽 — C. 오래 남은 종목

- 쉬운 제목: **“오래 붙어 있는 종목이 더 좋았나?”**
- streak 버킷 표 + scatter(있으면)
- 없으면: *“21일 성적이 아직 안 채워져 이 장은 다음 기회에”* 플레이스홀더

### 7쪽 — 후보 규모 추이 (가벼운 E)

- 쉬운 제목: **“후보 숫자가 너무 널뛰나?”**
- 풀 크기·median+·중앙값 선 그래프(또는 표)
- 급변 날 한 줄 표시

### 8쪽 — 부록 · 숫자 원표

- A–D 원표 CSV와 동일 수치 (전문용)
- 파일 위치: `reports/perf/study_* .csv`
- Release 태그·생성 시각·ledger 버전

## 5. 자동 문장 엔진 (초안 규칙)

페이지마다 **고정 템플릿** + 숫자 슬롯만 채움. LLM 자유 생성 없음(재현성).

예 (D쪽):

```text
【자료 {gate_한글}】 soft ceiling으로 뺀 종목의 {h}일 평균 성적은
시장 대비 {soft_pct}였고, 통과한 RS≥90 그룹은 {ok_pct}였습니다.
차이(뺀−통과)는 {delta_pct}입니다. {해석_문장}
```

`gate_한글`: 부족 / 지켜보는 중 / 해석 가능

## 6. 산출물 · 링크 (anal과 동일 패턴)

| 산출 | 경로/태그 |
|---|---|
| PDF | `reports/perf/검증보고서_YYYYMMDD.pdf` |
| MD 초안(선택) | `reports/perf/검증보고서_YYYYMMDD.md` (PDF와 같은 목차) |
| 차트 PNG | `reports/perf/charts/` (기존 + 보고서용 캡션 버전) |
| ZIP/boards | 선택 — Android용 |
| Release | 태그 `sepa-검증-YYYYMMDD` (또는 `sepa-verify-YYYYMMDD`) |
| 콘솔 | PDF 직접 URL + 릴리즈 페이지 URL **필수 출력** |

기존 기술 MD(`study_*.md`)는 유지하거나, 보고서 MD로 대체(권장: **보고서로 대체**, CSV는 유지).

## 9. 확정하면 좋은 선택지

1. **페이지 수**: 권장 8쪽 / 더 짧게 5쪽(A·D·한눈·부록만)?  
2. **Release 태그**: `sepa-검증-YYYYMMDD` vs `sepa-verify-YYYYMMDD`  
3. **기존 `study_*.md`**: 보고서로 대체 vs 둘 다 유지  
4. **Android ZIP/board**: V1에 넣을지, V2로 미룰지  

**권장**: 8쪽 · 태그 `sepa-검증-YYYYMMDD` · MD는 보고서 하나로 · ZIP/board는 V2.
