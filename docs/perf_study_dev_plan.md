# 개발 계획서 — 우리 모델이 잘 되는지 검사하는 도구 만들기

> **상태**: Phase 1 **구현됨** (`!sepa.perf_study` A–D)  
> **작성일**: 2026-08-04  
> **쉬운 버전**: 고등학생도 읽을 수 있게 다시 씀 (D29)  
> **자세한 기술 메모**: 같은 내용의 뼈대는 `docs/perf_study_framework.md`에도 있음

---

## 이 문서를 한 문장으로

우리는 매주 스크리너를 돌리면서 **성적표 재료는 이미 쌓고 있다.**  
이제 그 재료로 **“우리 규칙이 진짜 도움이 됐는지”를 자동으로 채점하는 시험 문제지**를 만들자는 계획이다.

---

## 1. 비유로 먼저 이해하기

학교를 생각하자.

| 학교 | 우리 프로젝트 |
|---|---|
| 매일 수업·시험 보기 | 매일/매주 `!sepa.go` 돌리기 |
| 시험 답안지 모아두기 | `reports/perf/`에 데이터 쌓기 |
| 중간·기말고사 성적 분석 | `!sepa.perf_study`로 성적표 만들기 |
| “이번엔 표본이 3주뿐” | 지금은 시험 횟수가 너무 적어 **확정 결론 금지** |
| “1년·2년 쌓이면 패턴 보임” | 몇 달·몇 년 돌리면 같은 방식으로 **점점 믿을 만해짐** |

중요한 점:

1. **데이터 모으는 통**은 이미 만들어 둠 (D28).
2. 지금 만들 것은 **채점 문제(분석 함수)** 다.
3. 지금 당장 “우리 모델 완벽하다/실패다”를 말하려는 게 **아니다**.  
   → **나중에 말해도 같은 방식으로 말할 수 있는 틀**을 짜는 것이다.

## 2. 우리가 이미 하고 있는 것 / 아직 부족한 것

### 이미 됨 (재료 창고)

`!sepa.go`를 돌릴 때마다 대략 이런 기록이 자동으로 남는다.

- 그날 후보 종목이 몇 개였는지
- Fund 점수 중앙값은 얼마였는지
- “중앙값 이상” 그룹, “RS 90 통과” 그룹, “soft ceiling으로 빠진” 그룹에 누가 들어갔는지
- 그날 뽑힌 종목이 **그 이후** 5일·10일·21일 동안 시장(S&P500)보다 잘했는지  
  (당일에는 아직 미래가 없어서 비워 두고, 나중에 go가 돌면 숫자를 채움)

→ 비유: **답안지는 매일 서랍에 넣고 있다.**

### 아직 약함 (채점표)

`!sepa.perf_study`는 **뼈대만** 있다.  
일부 숫자는 뽑지만, “우리가 진짜 궁금한 시험”이 아직 덜 정리돼 있다.

→ 비유: **채점 기준표와 그래프가 덜 만들어졌다.**

---

## 3. 우리가 답하고 싶은 질문 6개 (A~F)

각 질문은 **딱 하나**다.  
나중에 데이터가 많아지면 같은 질문을 다시 돌리면 된다.

### A. “우리가 고른 바구니가, 시장보다 나았나?”

- **쉬운 말**: 후보 전체 / 중앙값 이상 / 상위 25% / RS≥90 같은 **바구니**를 만들어 두고,  
  그 바구니 평균이 S&P500보다 잘 올랐는지 본다.
- **왜 중요?** 스크리너의 기본 성적표다.
- **지금**: 대충 있음 → 표·그래프를 더 알기 쉽게 다듬는다.

### B. “sepaTop에 새로 들어온 날 / 빠진 날, 그 뒤에 어땠나?”

- **쉬운 말**:  
  - **들어옴(enter)**: 편입 직후 성적이 좋았나?  
  - **나감(exit)**: 편출 직후 성적이 나빴나(잘 빼 냈나)?
- **왜 중요?** “타이밍이 맞는지”를 본다.
- **지금**: 한 줄 요약만 → 표와 그림으로 키운다.

### C. “오래 남아 있는 종목이 더 좋았나?”

- **쉬운 말**: 며칠 연속 리스트에 있는 종목(체류)과,  
  처음 본 날부터 한 번도 안 빠진 종목(always present)이  
  단기 성적과 관련이 있는지 본다.
- **왜 중요?** “자주 바꾸는 게 나은지 / 코어를 들고 가는 게 나은지” 힌트.
- **지금**: 상관계수 정도만 → 구간별(짧게/보통/길게)로 나눠 본다.

### D. “soft ceiling으로 뺀 종목이, 정말 빼도 되는 애들이었나?” *(가장 중요·아직 없음)*

쉬운 배경:

- 우리 규칙: RS가 90 이상이어도 **Fund가 그날 중앙값보다 낮으면** 탈락시킬 수 있다. (soft ceiling)
- 그래서 두 그룹이 생긴다.
  - **rs90_ok**: RS 높고, 규칙 통과해서 남은 애들
  - **soft_drop**: RS는 높았는데 Fund가 약해서 **우리가 뺀** 애들

질문:

> 뺀 애들(soft_drop)이, 남긴 애들(rs90_ok)보다 **그 다음에** 성적이 나빴는가?

- **왜 중요?** 지금 live 정책의핵심을 직접 검사하는 문제다.
- **지금**: **아직 안 만듦 → 1순위로 새로 만든다.**

### E. “후보자 수·중앙값이 날마다 너무 흔들리나?”

- **쉬운 말**: 풀 크기, median+ 개수, Fund 중앙값의 **시계열**을 본다.  
  갑자기 확 바뀐 날이 있으면 표시.
- **왜 중요?** “모델이 이상하게 요동친 날”을 빨리 발견.
- **지금**: 최근 며칠 표만 → 선 그래프로 키운다.

### F. “섹터·점수 구간까지 깊게 파기” *(나중)*

- **쉬운 말**: IT가 유독 잘했는지, Fund 상위가 하위보다 앞으로 더 잘했는지 등.
- **왜 나중?** 데이터가 꽤 쌓여야 의미가 있다.  
  A~E가 안정된 뒤에 한다.

## 4. 성적표를 믿으려면 “시험 횟수”가 필요하다

지금은 **약 3주**밖에 없다.  
그래서 리포트에는 항상 이런 안내가 붙는다.

| 단계 | 의미 | 비유 |
|---|---|---|
| **부족** | 숫자만 보여 주고, 결론 내리지 않음 | 퀴즈 3번 보고 “나는 수학 천재”라고 말하기 |
| **지켜보기** | 추세만 살핌 | 한 학기 중간고사 정도 |
| **해석 가능** | “대체로 이런 경향” 말하기 시작 | 몇 학기·몇 년 성적 |

계획은 **부족해도 리포트는 나오게** 만들고,  
데이터가 차면 같은 리포트가 저절로 더 쓸모 있어지게 한다.

## 5. 실제로 무엇을 만들 것인가

사용자가 하는 일(완성 후):

```text
1) 평소처럼   !sepa.go()
              → 재료가 자동으로 창고에 추가됨

2) 보고 싶을 때  !검증
              → 8쪽 한글 PDF + GitHub 다운로드 링크
              (동일: !sepa.perf_study() / !perf)
              양식: docs/verify_report_design.md
```

개발자가 만들 것:

- 질문 A~E를 각각 **함수(채점기)** 로 분리
- 표본이 적어도 **에러 나지 않고** “아직 부족”이라고 표시
- 결과는 `reports/perf/study_날짜.md` 같은 파일로 저장

프로덕션 규칙(RS 70, soft ceiling 등)은 **이 단계에서 바꾸지 않는다.**  
먼저 **측정**만 한다.

## 6. 만드는 순서 (3단계)

### 1단계 — 꼭 필요한 시험부터 (권장: 여기서 시작) ✅ 구현

1. A 성적표 다듬기  
2. B enter/exit 표·그림  
3. C 체류 구간 나누기  
4. **D soft_drop vs rs90_ok 새로 만들기**  
5. “표본 부족/지켜보기/해석” 딱지 붙이기  
6. 자동 테스트(가짜 데이터로 채점기가 맞게 도는지)

**끝 조건**: `!sepa.perf_study` 한 번에 A~D가 나오고, 데이터 적어도 안 죽는다. — **충족**

### 2단계 — 매일 보기 편하게

- E 풀 흔들림 그래프
- 원하면 A만, D만 따로 돌리기
- 성적표를 릴리즈/아티팩트에 더 잘 붙이기

### 3단계 — 데이터가 많아진 뒤

- F 섹터·점수 구간 깊은 분석
- (선택) 더 긴 기간(예: 3개월) 성적

## 7. 이 계획이 하지 않는 것

- “오늘 결과 보고 바로 RS/Fund 숫자 바꾸기” ❌  
- 완전한 자동매매 백테스트 엔진 다시 부활 ❌  
- “통계적으로 유의하니 무조건 진실” 선언 ❌  

하는 것:

- **같은 방식으로 오래 채점할 수 있는 도구** 만들기 ✅  
- soft ceiling 같은 **우리 규칙이 도움이 됐는지 숫자로 보기** ✅
