# SEPA 기반 기술적 매매 트레이딩 봇 — 개발 노트

> **프로젝트명**: Minervini SEPA Trading Bot
> **목표**: 마크 미너비니(Mark Minervini)의 SEPA(Specific Entry Point Analysis) 전략을 정량화하여, 나스닥 상장 기업을 대상으로 매수/매도 시그널을 생성하고 백테스트로 파라미터를 최적화하는 트레이딩 봇 구축
> **문서 버전**: v0.1 (기획 단계)
> **최종 수정일**: 2026-07-15

---

## 1. 프로젝트 개요

### 1.1 배경

마크 미너비니의 SEPA 전략은 다음 요소들의 결합으로 구성된 추세추종형 성장주 매매 기법이다.

| 구성 요소 | 내용 | 정량화 가능성 |
|---|---|---|
| Trend Template | 이동평균·52주 고저점 기반의 Stage 2(상승 추세) 판별 조건 8가지 | **높음** — 가격/거래량 데이터만으로 계산 가능 |
| VCP (Volatility Contraction Pattern) | 변동성 수축 패턴 기반의 진입 시점(피벗 포인트) 탐지 | **중간** — 패턴 정의를 알고리즘화해야 함 |
| 펀더멘털 필터 | 분기 EPS/매출 성장률 등 (Code 33 등) | **중간** — 재무 데이터 소스 필요, 1차 범위에서 제외 가능 |
| 리스크 관리 | 손절(-7~8%), 이익실현, 포지션 사이징 | **높음** — 규칙 기반 |

### 1.2 프로젝트 범위

- **포함**: 일봉(EOD) 기반 기술적 시그널 생성, 히스토리컬 백테스트, 파라미터 최적화
- **1차 범위에서 제외(추후 확장)**: 실시간 주문 집행(실거래 연동), 펀더멘털 데이터 통합, 인트라데이 매매
- **대상 유니버스**: 나스닥 상장 보통주 (ETF 제외) — 테스트 단계에서는 시가총액 상위 10개 종목

### 1.3 기술 스택 (제안)

| 영역 | 도구 | 비고 |
|---|---|---|
| 언어 | Python 3.11+ | 현재 리포지토리 기준 |
| 데이터 수집 | `yfinance` (1차), Alpha Vantage / Polygon.io (대안) | "크롤링"보다 공식 API 사용 권장 — 안정성·법적 리스크 측면 |
| 데이터 처리 | `pandas`, `numpy` | |
| 저장 형식 | Parquet (종목별 파일) + 메타데이터 카탈로그 | 종목 추가에 유연한 구조 |
| 백테스트 | 자체 엔진 또는 `vectorbt` / `backtrader` | Phase 3에서 결정 |
| 시각화 | `matplotlib`, `plotly` | 시그널 검증용 차트 |

### Phase 1. 전략 정량화 및 데이터 요건 정의

| 항목 | 내용 |
|---|---|
| 목표 | SEPA 전략의 모든 규칙을 수식/의사코드 수준으로 명세하고, 계산에 필요한 데이터 필드 목록 확정 |
| 입력 | 미너비니 저서 및 공개 자료의 규칙, 사용자의 해석·우선순위 |
| 산출물 | ① 전략 명세서 (`docs/strategy_spec.md`) ② 데이터 요건 정의서 (필드·주기·기간) |
| 완료 기준 | 명세서만 보고 제3자가 동일한 시그널 로직을 구현할 수 있는 수준 |

**정량화 대상 — Trend Template 8개 조건 (기본값)**:

1. 현재가 > 150일 이동평균(SMA150) 그리고 > 200일 이동평균(SMA200)
2. SMA150 > SMA200
3. SMA200이 최소 1개월(권장 4~5개월) 이상 상승 추세
4. SMA50 > SMA150 > SMA200
5. 현재가 > SMA50
6. 현재가가 52주 최저가 대비 최소 +30% 이상
7. 현재가가 52주 최고가 대비 -25% 이내
8. 상대강도(RS) 순위 70 이상 (권장 80~90 이상) — *유니버스 내 상대 계산 필요*

**필요 데이터 필드 (예상)**:

- 일봉 OHLCV (수정주가 기준, 최소 2년치 — 200일 SMA 웜업 + 백테스트 구간 확보)
- 종목 메타데이터: 티커, 종목명, 거래소, 증권 유형(ETF 필터링용), 섹터/산업
- (선택) 분기 실적: EPS, 매출 — 펀더멘털 필터 확장 시

### Phase 2. 파일럿 데이터 파이프라인 (나스닥 상위 10개 종목)

| 항목 | 내용 |
|---|---|
| 목표 | 상위 10개 종목의 데이터를 수집·정제하여 **종목 수 확장이 자유로운** 데이터 구조 확립 |
| 입력 | Phase 1의 데이터 요건 정의서, 데이터 소스 선택 |
| 산출물 | ① 수집 스크립트 ② 정제 파이프라인 ③ 종목별 Parquet + 유니버스 카탈로그(CSV/JSON) |
| 완료 기준 | `config/universe.yaml`에 티커 1줄 추가만으로 신규 종목이 파이프라인에 편입됨 |

**확장 가능한 데이터 구조 설계 원칙**:

- **종목별 1파일** (`data/raw/{ticker}.parquet`) — 종목 추가/삭제가 다른 데이터에 영향 없음
- **유니버스 카탈로그 분리** — 종목 목록은 데이터가 아닌 설정으로 관리
- **스키마 고정** — 모든 종목이 동일한 컬럼 스키마 (`date, open, high, low, close, adj_close, volume`)
- **증분 업데이트 지원** — 전체 재수집 없이 최신 일자만 추가 가능하게

**정제 체크리스트**:

- [ ] 수정주가(액면분할·배당 반영) 여부 확인 — 백테스트 왜곡의 최대 원인
- [ ] 결측일 처리 정책 (거래정지일 등)
- [ ] 이상치 검출 (일간 변동률 임계값 초과 시 플래그)
- [ ] 시간대·거래일 캘린더 일관성

### Phase 3. 시그널 모델 구축 (매수/매도 함수)

| 항목 | 내용 |
|---|---|
| 목표 | 파라미터를 입력받아 종목별 매수/매도 타이밍을 반환하는 순수 함수형 모델 구현 |
| 입력 | Phase 1 전략 명세서, Phase 2 정제 데이터 |
| 산출물 | ① `generate_signals(df, params) -> signals` 함수 ② 파라미터 스키마 정의 ③ 시그널 시각화 노트북 ④ 단위 테스트 |
| 완료 기준 | 상위 10개 종목의 최근 2년 차트에서 시그널을 눈으로 검증(육안 대조)했을 때 전략 의도와 일치 |

**매수 로직 (2단계 게이트)**:

1. **자격 필터**: Trend Template 8개 조건 전부 통과 (Stage 2 확인)
2. **진입 트리거**: VCP 피벗 돌파 — 수축 구간 저항선을 평균 이상 거래량으로 상향 돌파
   - *1차 구현 대안*: VCP 알고리즘화가 어려우면 "N주 신고가 돌파 + 거래량 조건"으로 단순화 후 고도화

**매도 로직**:

- 손절: 매수가 대비 `stop_loss_pct` (기본 -7~8%) 하회
- 추세 이탈: 종가가 SMA50 하회 N일 지속 등
- (선택) 트레일링 스탑, 목표 수익률 부분 청산

**파라미터 목록 (초안)**:

| 파라미터 | 기본값 | 탐색 범위(예) |
|---|---|---|
| `sma_short / mid / long` | 50 / 150 / 200 | 고정 권장 (전략 정체성) |
| `low_52w_min_pct` | +30% | 25~40% |
| `high_52w_max_pct` | -25% | -15~-30% |
| `rs_rank_min` | 70 | 70~90 |
| `pivot_volume_mult` | 1.5× (50일 평균 대비) | 1.2~2.0 |
| `stop_loss_pct` | -8% | -5~-10% |
| `trail_exit_ma` | SMA50 | SMA20~SMA50 |

**설계 원칙**: 시그널 생성은 상태를 갖지 않는 순수 함수로 — 백테스트와 실시간 운용에서 동일 코드 재사용.

### Phase 4. 전체 유니버스 확장 (나스닥 전 종목, ETF 제외)

| 항목 | 내용 |
|---|---|
| 목표 | Phase 2 파이프라인을 그대로 사용하여 나스닥 전 상장 보통주(~3,000+ 종목)로 데이터 확장 |
| 입력 | 나스닥 상장 목록 (Nasdaq Trader `nasdaqlisted.txt` — ETF 플래그 포함), Phase 2 파이프라인 |
| 산출물 | 전 종목 데이터셋 + 수집 실패/제외 종목 로그 |
| 완료 기준 | 유니버스의 95% 이상 수집 성공, 데이터 품질 검사 통과 |

**주의사항**:

- **생존 편향(Survivorship Bias)**: 현재 상장 종목만 수집하면 상장폐지 종목이 빠져 백테스트 수익률이 과대평가됨. 최소한 이 한계를 문서화하고, 가능하면 상장폐지 포함 데이터 소스 검토
- API 호출 제한(rate limit) 대응 — 배치 처리, 재시도 로직, 진행 상태 저장
- 저유동성 종목 필터 기준 사전 정의 (예: 평균 거래대금, 최소 주가)

### Phase 5. 백테스트 및 파라미터 최적화

| 항목 | 내용 |
|---|---|
| 목표 | 트레이닝/테스트 구간 분리 하에 최적 파라미터 도출 및 과최적화 검증 |
| 입력 | Phase 3 모델, Phase 4 전체 데이터 |
| 산출물 | ① 백테스트 엔진(체결·수수료·슬리피지 모델 포함) ② 파라미터 탐색 결과 리포트 ③ 최종 성과 리포트 |
| 완료 기준 | 테스트 구간(out-of-sample)에서 벤치마크(QQQ 매수 후 보유) 대비 위험조정수익률 비교 리포트 완성 |

**핵심 설계 결정**:

- **데이터 분할은 시계열 기준** (무작위 분할 금지): 예) 트레이닝 2016–2021 / 테스트 2022–2026
- **워크포워드(Walk-Forward) 검증 권장**: 단일 분할보다 견고 — 롤링 윈도우로 재최적화·재검증 반복
- **미래 참조(Look-Ahead) 금지**: 시그널은 T일 종가까지 정보로 계산, 체결은 T+1일 시가
- **평가지표는 수익률 단독 금지**: CAGR + 최대낙폭(MDD) + 샤프비율 + 승률 + 거래횟수 종합
- **포트폴리오 규칙 필요**: 동시 시그널 다수 발생 시 선택 기준(RS 순위 등), 최대 보유 종목 수, 종목당 배분 비율
- **거래 비용 모델**: 수수료 + 슬리피지 미반영 시 결과가 실전과 크게 달라짐

## 3. 각 단계에서 사용자가 제공하면 효과가 커지는 요소

> 단계 착수 시 아래 항목을 함께 제시해 주면, 재작업 없이 한 번에 의도에 맞는 결과물을 만들 수 있다.

### Phase 0 — 기반 구축

- **실행 환경**: 로컬 PC / 클라우드 / 스케줄 실행(매일 장 마감 후 자동 실행 등) 여부
- **최종 사용 형태**: CLI 스크립트, 노트북, 웹 대시보드, 알림(텔레그램/이메일) 중 무엇을 원하는지

### Phase 1 — 전략 정량화

- **전략 해석의 우선순위**: 미너비니 규칙 중 반드시 지킬 것 vs. 완화 가능한 것 (예: RS 순위 기준 70? 90?)
- **펀더멘털 포함 여부**: 1차 버전에서 기술적 지표만 쓸지, EPS 성장률 필터까지 넣을지 — 데이터 소스와 복잡도가 크게 달라짐
- **참고 자료**: 특히 따르고 싶은 책의 장(章), 인터뷰, 또는 본인이 정리해 둔 규칙 노트가 있다면 공유
- **매매 주기 확정**: 일봉 기준 스윙(수 주~수 개월 보유)인지 확인 — 데이터 주기·수집량이 여기서 결정됨

### Phase 2 — 파일럿 데이터 파이프라인

- **데이터 소스 선호/보유 API 키**: 유료 API(Polygon, Alpha Vantage 등) 키 보유 여부. 없으면 yfinance로 시작
- **"상위 10개"의 기준**: 시가총액 기준인지, 특정 시점 기준인지, 아니면 직접 지정할 10개 티커가 있는지
- **수집 기간**: 백테스트를 몇 년치로 할 계획인지 (권장: 최소 8~10년 — 강세장·약세장 모두 포함)
- **저장 형식 제약**: 엑셀로도 봐야 하는지, DB를 쓰고 싶은지 등

### Phase 3 — 시그널 모델

- **VCP 처리 방침**: VCP를 엄밀히 알고리즘화할지, 1차에서는 단순 돌파 규칙으로 대체할지 — 개발 난이도의 최대 변수
- **매도 규칙 우선순위**: 손절 폭, 추세 이탈 기준 등 본인이 감내할 수 있는 낙폭 수준
- **검증에 쓸 기준 사례**: "이 종목의 이 시점은 매수 시그널이 나와야 한다"는 정답 사례 몇 개 (예: 2020년 특정 종목 돌파 시점) — 모델 검증 품질이 크게 올라감

### Phase 4 — 전체 유니버스 확장

- **유니버스 필터 기준**: 최소 시가총액, 최소 주가(저가주 제외 여부), 최소 거래대금
- **생존 편향 대응 수준**: 한계 문서화로 충분한지, 상장폐지 포함 유료 데이터까지 검토할지
- **인프라 제약**: 수집에 수 시간이 걸릴 수 있음 — 실행 가능한 시간대/환경

### Phase 5 — 백테스트·최적화

- **트레이닝/테스트 분할 시점**: 어느 연도로 나눌지 (또는 워크포워드 채택 여부)
- **초기 자본금·포지션 규칙**: 총 자본, 종목당 최대 비중, 동시 보유 종목 수 상한
- **거래 비용 가정**: 사용하는 증권사 수수료율, 예상 슬리피지
- **최우선 평가지표**: 절대수익률 vs. 위험조정수익률(샤프) vs. 최대낙폭 최소화 — 최적화의 목적함수가 달라짐
- **벤치마크**: QQQ(나스닥100) 대비 비교로 충분한지
