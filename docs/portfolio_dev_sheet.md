## 1. 한 줄 정의

사용자가 변동을 알려주면 포트폴리오 DB를 갱신하고,  
`!portfolio` / `!portfolio.anal` 등으로 **차트·손익·체크포인트·뉴스·향후 전략(+이유)** 을 출력하는 매크로 봇.

기존 SEPA 파이프라인(`scan → fund → anal`)과는 **분리**.  
SEPA는 “무엇을 볼지”, portfolio는 “내가 이미 산 것을 어떻게 관리할지”.

---

## 2. 사용자가 말한 요구사항 (확정 초안)

| # | 요구 | 비고 |
|---|---|---|
| R1 | 매수 기업·시점·가격을 전달 → 저장 | 변동 시마다 채팅으로 알려줌 → 에이전트가 데이터 업데이트 |
| R2 | 분석 요청 시 **미래 전략** 제안 | 반드시 **그렇게 생각한 이유** 첨부 |
| R3 | 매수 시점부터 **가격 변화 그래프** | 증권사 앱 느낌의 시각화 + 이익/손실률 |
| R4 | 종목별 **직접 체크할 중요 이벤트** | 가독성 좋게 정리 |
| R5 | **공신력 있는 금융 뉴스**의 굵직한 이슈 | 판단 참고용 |

## 3. 구현 전에 필요한 정보 (사용자 제공)

합의·구현을 위해 아래를 확정해 주세요. (모르면 “나중에” / 기본값 제안 가능)

### 3.1 포트폴리오 기본

| 항목 | 왜 필요 | 예시 / 기본 제안 |
|---|---|---|
| **통화** | 손익·시총 표기 | USD (나스닥 위주라면) |
| **기준 환율** | 원화 병기 여부 | 원하면 선택 / 1차는 USD만 |
| **총 투자 원금 or 현금 잔고** | 비중·리밸런싱 | 종목 합만으로도 가능(현금 0 가정) |
| **계좌/브로커** | 수수료·세금 가정 | “무시” 기본 가능 |
| **포지션 단위** | 주수 vs 금액 | **주수(shares) + 단가** 권장 |

### 3.2 매매 기록에 넣을 필드

**최소(필수)**  
- 티커  
- 매수일 (YYYY-MM-DD)  
- 매수 단가  
- 수량(주)

**권장(있으면 분석 품질↑)**  
- 매도일 / 매도 단가 / 매도 수량 (부분 매도 지원)  
- 수수료·슬리피지 (없으면 0)  
- 메모 (매수 이유: “SEPA Stage2 + Fund 50” 등)  
- 목표 비중 또는 최대 손실 한도 (종목/%)

### 3.3 분석·전략 기준 (증권사 직원 역할용)

| 항목 | 질문 | 기본 제안 |
|---|---|---|
| 투자  horizon | 스윙(수 주~수 개월) / 중기? | SEPA와 맞춰 **스윙~중기** |
| 손절 규칙 | 고정 %? 추세 이탈? | 미너비니식 **-7~8%** 또는 추세(SMA50) 이탈 |
| 익절/트레일 | 목표 % / 피벗 기준? | 1차는 “추세 유지 시 보유, 이탈 시 축소” |
| 집중도 | 한 종목 최대 비중? | 예: 단일 종목 ≤ 25% |
| 뉴스 언어 | 영문만 / 한글 요약 | **영문 소스 + 한국어 요약** |
| 알림 | 매일 자동 vs 요청 시만 | **요청 시만** (`!portfolio`) |

### 3.4 첫 포트폴리오 입력 형식 (합의용)

채팅에 이렇게 주시면 저장하기 좋습니다:

```text
!portfolio.add
NVDA, 2026-06-01, 120.50, 10
AMD, 2026-06-15, 160.00, 5
```

또는 자연어:

```text
6월 1일 NVDA 10주 @120.50, 6월 15일 AMD 5주 @160 매수했어. 반영해줘.
```

## 4. 제안하는 매크로 UX

| 명령 | 역할 |
|---|---|
| `!portfolio` / `!portfolio.status` | 현재 보유·비중·평가손익 요약 |
| `!portfolio.add(...)` | 매수(또는 추가 매수) 기록 |
| `!portfolio.sell(...)` | 전량/부분 매도 기록 |
| `!portfolio.anal` / `!portfolio.go` | 전체 분석 리포트 (차트+이벤트+뉴스+전략) |
| `!portfolio.chart(TICKER)` | 단일 종목 매수 이후 차트 |
| `!portfolio.show` | 원장(거래 내역) 텍스트/CSV 경로 |

별칭: `!pf` = `!portfolio` (선택).

## 5. 데이터·저장 설계 (초안)

```
data/portfolio/
  positions.yaml      # 또는 ledger.csv — 거래 원장(append-only 권장)
  meta.yaml           # 통화, 현금, 규칙(손절% 등)
reports/portfolio/
  summary_YYYYMMDD.csv
  charts/
    pf_NVDA_YYYYMMDD.png
    pf_allocation_YYYYMMDD.png
    pf_equity_YYYYMMDD.png
```

- **원장(ledger) 방식**: 매수/매도를 거래 행으로만 쌓고, 현재 포지션은 집계.  
  → 부분 매도·평단 변경에 유리.
- 가격: 기존 `data/raw/{TICKER}.parquet` 증분 캐시 재사용 (+ 없으면 수집).

## 6. 분석 리포트 구성 (출력 순서)

1. **스냅샷** — 종목별 평단, 현재가, 수익률, 평가금액, 포트 비중  
2. **시각화**  
   - 종목별: 매수일 마커 + 매수 이후 가격 곡선 + 손익%  
   - 포트: 비중 파이/막대, (선택) 가상 자산 곡선  
3. **종목별 체크리스트** — 실적 발표일, 옵션만기·락업 등 알 수 있는 일정, SEPA 관점(추세/RS/근접 지지)  
4. **뉴스 이슈** — 공신력 소스만, 종목당 소수 헤드라인 + 한 줄 시사점  
5. **전략 제안** — 보유/축소/추가관심/손절 감시 등 + **반드시 이유**  
6. **리스크 메모** — 섹터 편중, 단일 종목 과다, Fund=0/소형주 잔존 여부 등

Android에서는 차트를 **Artifacts 링크**로 안내 (기존 `anal`과 동일).

## 7. 기술 접근

| 영역 | 방안 |
|---|---|
| 저장 | YAML/CSV 원장 + git에 메타만 또는 `data/portfolio/` gitignore(개인정보) — **합의 필요** |
| 가격 | 기존 `sepa.data.store` |
| 차트 | matplotlib, “앱 카드” 느낌(다크 최소화, 명확한 손익 색: 녹/적은 사용자 취향 확인) |
| 실적·이벤트 | yfinance calendar / earnings dates (가능한 범위) |
| 뉴스 | 허용 도메인만 (아래 8절). 에이전트가 웹검색·요약. 자동 스크래핑은 라이선스·차단 리스크 → **검색 API/공개 RSS·헤드라인** 우선 |
| 전략 엔진 | 규칙 기반(손절·비중·추세) + LLM이 이유 문장 작성 (할루시네이션 방지: 숫자·뉴스는 도구 결과에만 근거) |

## 9. 제가 제안하는 추가·수정 (합의 포인트)

### 추가하면 좋은 것

| 제안 | 이유 |
|---|---|
| **A1. 거래 원장(부분 매도·물타기)** | 실전 포트는 한 줄 매수로 끝나지 않음 |
| **A2. 현금·미실현/실현 손익 분리** | “지금까지 번 것” vs “장부 평가” 구분 |
| **A3. SEPA 교차 표시** | 보유 종목이 지금 Stage2/Fund/섹터 어디에 있는지 한눈에 |
| **A4. 이벤트 캘린더 우선순위** | 실적 > 가이던스/공시 > 섹터 규제 뉴스 순 |
| **A5. 전략 템플릿 고정** | 예: 감시 / 축소 검토 / 유지 / (신중) 추가 — 중구난방 조언 방지 |
| **A6. `data/portfolio` 비공개(gitignore)** | 매수 단가는 민감 정보 |
| **A7. 분석 시 “가정” 명시** | 수수료 0, 환율 미적용 등 |

### 수정·완화 제안

| 원 요구 | 제안 |
|---|---|
| “증권사 앱 같은 디자인” | 1차는 **깔끔한 카드형 정적 PNG** (인터랙티브 앱 UI는 범위 큼) |
| “미래 전략을 자동으로” | **매 입력마다 자동 장문 전략**보다는, 저장은 자동·**전략은 `!portfolio.anal` 요청 시** (비용·노이즈↓). 원하면 `add` 직후 짧은 3줄 코멘트만 |
| “공신력 뉴스” | 실시간 풀 텍스트 보장 어려움 → **헤드라인+링크+요약**이 현실적 |
| 손익 색 | 한국 앱은 보통 상승=적 / 미국=녹. **선호 확인** |

### 범위에서 빼는 것 (1차)

- 실주문·증권사 API 연동  
- 세금 최적화  
- 자동 매매 시그널 집행

## 10. 개발 단계 (합의 후)

| Phase | 내용 | 완료 기준 |
|---|---|---|
| P0 | 원장 스키마 + `add`/`sell`/`show` + 파일 저장 | 채팅 한 번으로 포지션 갱신·조회 |
| P1 | 평가손익·비중 표 + 종목/포트 차트 | PNG Artifacts + 손익% |
| P2 | 이벤트 체크리스트 (실적일 등) | 종목별 불릿 |
| P3 | 뉴스 헤드라인(화이트리스트) | 종목당 소수 이슈 |
| P4 | 전략 템플릿 + 이유 문장 | `anal` 한 번에 1~5 출력 |

기존 매크로와 동일하게 `REGISTRY` 등록, `!tools`에 노출.
